What it does

我把工作紀錄這件事做成一個小工具

原本需要透過 AI 來串接日曆、彙整當週事項，我試著將這個 skill 寫成了網頁小工具。

GROUPING01
自動分組

同一集、同一類型的工作會自動歸在一起，列出細項。

HOURS02
時數加總

自動算出每組時數與本週總計，精確到 0.5 小時。

COPY03
一鍵複製

整理結果可直接複製成純文字，貼進週報或訊息。

開啟 WeeklyBrief

網址：redmoon30.github.io/WeeklyBrief/ | 建議加進書籤

關於你的資料

你的日曆資料不會被傳到任何伺服器——登入、讀取、彙整全部在你自己的瀏覽器裡完成。
關掉分頁後授權就失效，工具端不保存任何東西，也看不到你的日曆。

工具只要求「日曆唯讀」權限，無法新增、修改或刪除你的任何行程。

Why calendar

隨手記錄你的工作

在做成週報之前，就讓工作紀錄成為良好的習慣

1
設定提醒，不怕錯過

日曆通知確保你不會漏掉會議和截止日，比靠記憶可靠。

2
工作時長，一眼可視

色塊讓你把一週的負荷分布看清楚，調整工作量有依據。

3
提前規劃，下週不慌

週五花五分鐘把下週任務拉進日曆，週一開工就知道要做什麼。

習慣建立好，週五早上開 WeeklyBrief → 複製 → 貼上 Notion，全程不到 30 秒。

How to use

不用安裝任何東西，照著做就對了

用電腦的瀏覽器開啟就能用（手機也可以，但建議用電腦操作比較方便）。

01
打開工具，點「用 Google 登入」
建議將網址加入書籤：redmoon30.github.io/WeeklyBrief/
|
02
選擇你的帳號，同意查看日曆
會跳出 Google 的授權視窗。
若出現「Google 尚未驗證」，點「進階」→「前往 WeeklyBrief」，這是測試階段的正常提示。
|
03
選取要彙整的日曆
下拉選單會列出你帳號底下所有日曆。選你記工作的那一本。
|
04
按「產生本週彙整」，看結果，複製
複製出來是純文字，可以直接貼進週報、Line 或 Slack。

每次打開都要重新登入一次——這是刻意的設計，因為工具不保存你的授權。

Reading the result

看懂彙整結果

結果分成兩區：有集數編號的工作會分組加總，其他工作各自列出。

畫面上的三種行

看到什麼意思
粗體的一行分組標題，右邊是這組的加總時數（例：ep08 Storyboard feedback　13hr）
縮排的一行這組底下實際的日曆事件，讓你核對加總對不對
沒有縮排、也不是粗體沒有集數編號、也沒有和其他事件合併的獨立工作

兩個實用功能

EDIT
雙擊任一行文字可以直接改

日曆標題打太簡略或有錯字時，不用回去改。
Enter 存檔、Esc 取消。不影響原始日曆。

COPY
「複製本週彙整」會照畫面現況複製

包含你手改過的文字，貼到哪裡都不會跑版。

底部的總計是本週所有事件的時數總和，不受分組方式影響。

Naming rules

日曆標題可以怎麼寫

照這幾條規則寫，工具就會依照事件標題文字分組。如果有其他工作分組建議，都可以反饋給拉瓦。

1
寫上 ep + 數字，歸到那一集
例：ep08 分鏡 → 歸到 EP08。
大小寫、有無空格都可以：ep08 / EP 8
2
加上工作類型關鍵字，自動分類
例：ep02 SB Scene 12 → 歸到 EP02 的 Storyboard。
關鍵字對照見下表
3
有集數但沒寫類型，也會自動歸類
會併入該集時數最多的類型——不用每筆都標。
4
加上 feedback / 回覆，自動標記
例：ep02 Layout 回覆導演筆記 → 標籤顯示「ep02 Layout feedback」。
5
沒有集數的獨立工作，各自列出
例：「團隊會議」「弘元開會」→ 各自一行，不會被硬塞到「其他」。
